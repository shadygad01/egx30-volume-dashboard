# EGX30 Volume Zones Dashboard

لوحة تحليل يومية لأسهم **EGX30** تهدف إلى تنظيم بيانات OHLCV المتاحة، واكتشاف مناطق تركّز الحجم السعري، وتصنيفها بشكل محافظ إلى **Potential Accumulation** و**Potential Distribution** و**Neutral**. اللوحة أداة مراقبة وتحليل كمي وليست توصية شراء أو بيع، ولا تستبدل التحقق المستقل أو المشورة الاستثمارية المتخصصة.

> **مبدأ المشروع:** لا توجد بيانات مصطنعة. إذا لم تصل بيانات حقيقية صالحة من المصدر، يعرض النظام `No data` أو حالة خطأ واضحة، ولا ينشئ أسعارًا أو أحجامًا أو مناطق بديلة.

## 1. ما الذي تقدمه اللوحة؟

تبدأ اللوحة من بيانات يومية حقيقية لكل رمز متاح من قائمة المتابعة. تُخزّن حقول الافتتاح والأعلى والأدنى والإغلاق والحجم، ثم تُحلّل كل جلسة بوصفها نافذة زمنية يومية. يحتفظ النظام أيضًا بتاريخ الجلسات والمناطق والتنبيهات حتى يمكن مقارنة الإغلاق الأخير بالإغلاق السابق، وفتح تفاصيل سهم بعينه، ومراجعة ما حدث في تشغيلات التحليل السابقة.

تتكون واجهة الداشبورد من الأقسام الآتية:

| القسم             | الاستخدام                                                                                             |
| ----------------- | ----------------------------------------------------------------------------------------------------- |
| **Overview**      | ملخص السوق، مؤشرات الكون المتابع، Accumulation watch، خريطة الحجم، ترتيب الأسهم، والمناطق الاتجاهية.  |
| **History**       | مقارنة أحدث جلستين متاحتين، وتاريخ يصل إلى 90 جلسة محفوظة للسهم المختار.                              |
| **Stock detail**  | الشموع، نطاقات الأسعار والحجم، حالة المنطقة `Active` أو `Historical`، وتأكيد السعر بعد 1 و3 و5 جلسات. |
| **Alert history** | سجل التشغيلات، حالة إرسال التنبيه، الرموز والنطاقات المحفوظة، مع البحث والنقر لفتح تفاصيل السهم.      |
| **Methodology**   | شرح القيود، معنى التصنيفات، قاعدة الترتيب، ومعدل التحديث.                                             |
| **Settings**      | إعدادات المالك: قائمة المتابعة، مصدر البيانات، الجدولة، ومدة نافذة المنطقة النشطة.                    |

## 2. طريقة استخدام الداشبورد

### 2.1 قراءة Overview

عند فتح اللوحة، ابدأ من الشريط العلوي. يعرض هذا الشريط تاريخ اليوم، وآخر إغلاق تاريخي تم التحقق منه، حالة آخر تشغيل، ومدة **Active window** الحالية. إذا ظهرت عبارة `Awaiting first run` أو `No data` فهذا يعني أن النظام لم يجد تشغيلًا أو صفوفًا صالحة لعرضها، وليس أن النظام قدّر قيمة مفقودة.

يمكن استخدام مرشحي **Direction** و**Confidence** لتضييق المناطق الظاهرة. مرشح الاتجاه يختار بين Potential Accumulation وPotential Distribution وNeutral، بينما يختار مرشح الثقة بين High وMedium وLow. إذا لم ينتج عن المرشحات صفوف، تعرض الواجهة حالة عدم تطابق صريحة.

تُرتب الأسهم افتراضيًا من الأعلى أهمية تحليلية إلى الأقل وفق القاعدة التالية:

1. Potential Accumulation أولًا.
2. داخل التجميع، High ثم Medium ثم Low.
3. بعد ذلك Potential Distribution ثم Neutral.
4. داخل المجموعة نفسها، Strength Score تنازليًا، ثم الحجم النسبي، ثم ترتيب مصدر ثابت للتعادل التام.

لا تدخل تأكيدات السعر بعد 1 أو 3 أو 5 جلسات في الترتيب الافتراضي؛ فهي مقياس متابعة لاحق وليست جزءًا من أولوية الاكتشاف الأولي.

### 2.2 فهم خريطة الحجم والقوائم المرتبة

خريطة الحجم تعرض قوة النشاط النسبي لكل سهم بالنسبة إلى خط الأساس المتاح له. لا تعني الخريطة أن السهم قابل للشراء، بل تشير إلى أن حجمًا غير اعتيادي ظهر بجوار سلوك سعري يستحق المراجعة. تُظهر القوائم رقم الترتيب وStrength Score وبعض شارات الاتجاه والثقة لتوضيح سبب ظهور السهم في موضعه.

### 2.3 فتح Stock detail

يمكن النقر على رمز السهم أو على رمز محفوظ في Alert history. يعرض Stock detail آخر البيانات اليومية المحفوظة، ونطاقات الأسعار، والمناطق الناتجة فعليًا من البيانات، إضافة إلى شارة:

| الشارة         | معناها                                                                           |
| -------------- | -------------------------------------------------------------------------------- |
| **Active**     | منطقة تقع داخل نافذة الجلسات الحالية التي يستخدمها آخر تشغيل تحليل.              |
| **Historical** | منطقة محفوظة من جلسات سابقة، متاحة للتاريخ لكنها ليست ضمن اللقطة النشطة الحالية. |
| **No data**    | لا توجد صفوف كافية أو صالحة لإجراء الحكم المطلوب.                                |

يعرض قسم التأكيد نتيجة ما حدث بعد المنطقة عند توفر جلسات لاحقة: `Upward break` أو `Downward break` أو `Within zone` أو `No data`. هذه النتائج وصف تاريخي للسلوك المسجل وليست توقعًا للمستقبل.

### 2.4 استخدام History

يعرض History أحدث جلسة محفوظة مقابل الجلسة السابقة لكل سهم متاح. تشمل المقارنة الإغلاق، التغير المطلق، التغير النسبي، والحجم. وعند اختيار سهم، يمكن مراجعة سلسلة تاريخية تصل إلى 90 جلسة محفوظة. يعتمد هذا القسم على قاعدة البيانات فقط ولا يجلب قيمة بديلة عند غياب الجلسة.

### 2.5 استخدام Alert history

يحتفظ Alert history بحالات تشغيل التحليل والتنبيه: `sent` أو `skipped` أو `failed`. البحث يطابق الرموز والنطاقات النصية المحفوظة فعليًا فقط، وهو غير حساس لحالة الأحرف. النقر على رمز أو نطاق يحدد الرمز بصيغة `.EGX` ويفتح Stock detail.

التنبيه التلقائي لا يرسل كل المناطق. القاعدة الحالية تقتصر على مناطق **Potential Accumulation** ذات الثقة **High** التي ظهرت في جلسة جديدة، مع منع التكرار عبر منطق deduplication. لا يُنشئ النظام تنبيهًا إذا لم توجد منطقة عالية الثقة حقيقية.

## 3. إعدادات المالك

صفحة Settings محمية بتسجيل الدخول، بينما تبقى القراءة العامة للوحة متاحة دون تسجيل دخول. يمكن للمالك تعديل قائمة الرموز وحفظ مدة نافذة المناطق النشطة من القيم المسموح بها: **5، 10، 20، أو 30 جلسة تداول**. القيمة الافتراضية هي 10 جلسات.

تغيير مدة النافذة يحفظ الإعداد ويظهر للمستخدم كحالة `pending-reanalysis`. لا يعيد النظام كتابة آخر تشغيل بأثر رجعي فور الضغط على Save؛ يطبق الإعداد في التشغيل اليومي التالي. هذه القاعدة تمنع خلط إعداد جديد مع بيانات قديمة لم تُحلل وفقه.

تعرض Settings كذلك حالة مصدر البيانات، حالة الجدولة، آخر تشغيل ناجح، وآخر خطأ إن وجد. لا يحتاج مسار Yahoo المجاني إلى API key مدفوع.

## 4. مصدر البيانات وحدوده

يستخدم المسار الحالي طلبات Yahoo Finance Chart API العامة للحصول على بيانات يومية `interval=1d`. يحول النظام رموز EGX إلى رمز Yahoo المقابل بإزالة لاحقة `.EGX` وإضافة `.CA` عند الحاجة. تُقبل الصفوف فقط إذا كانت جميع قيم OHLCV رقمية وصالحة.

| الحقيقة التشغيلية                                        | أثرها                                                                                                                       |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| المصدر مجاني                                             | لا توجد تكلفة API key في المسار الحالي.                                                                                     |
| المصدر يومي                                              | لا توجد شموع ساعتين حقيقية في المسار المجاني الحالي.                                                                        |
| التغطية ليست مضمونة لكل الرموز                           | قد تظهر رموز بلا صفوف، وتظل بلا بيانات بدل تصنيع صفوف لها.                                                                  |
| قد يختلف تاريخ الاقتباس الحالي عن آخر تاريخ تاريخي مكتمل | يعرض النظام `Last verified close` من السلسلة التاريخية المقبولة فقط.                                                        |
| شروط إعادة التوزيع تعتمد على المصدر                      | الملف [free_source_research.md](./free_source_research.md) يسجل قيود المصدر، ويجب مراجعة شروط Yahoo قبل إعادة نشر البيانات. |

> **مهم:** لا يحول النظام البيانات اليومية إلى بيانات ساعتين مصطنعة. توجد دالة تجميع ساعتين في الطبقة المشتركة لاستخدامها عندما تتوفر نقاط intraday حقيقية، لكن `fetchFreeIntraday()` يعيد مصفوفة فارغة في وضع Yahoo اليومي الحالي. لذلك تعرض الواجهة حدود هذا الوضع بدل الادعاء بوجود حجم داخل الجلسة.

## 5. منهجية التحليل

### 5.1 بناء الملخص اليومي

لكل جلسة، تُحسب النسبة الحجمية من خلال قسمة حجم الجلسة على متوسط الأحجام المتاحة في نافذة التحليل. كما يُحسب نطاق السعر كنسبة مئوية من الإغلاق. عند وجود نقاط intraday حقيقية مستقبلًا، يمكن تجميعها إلى نوافذ ساعتين باستخدام Open لأول نقطة، Close لآخر نقطة، وأعلى وأدنى وحجم مجموع داخل النافذة.

### 5.2 حساب درجة المنطقة

تُبنى درجة المنطقة من ثلاثة مكونات محافظة:

| المكوّن               | الوزن | الفكرة                                             |
| --------------------- | ----: | -------------------------------------------------- |
| Volume score          |   45% | قوة الحجم النسبي، مع سقف تطبيقي عند ضعف خط الأساس. |
| Price acceptance      |   30% | هل يتداخل نطاق السعر مع النطاق السابق أم لا؟       |
| Narrow-range behavior |   25% | هل النطاق الحالي قريب من وسيط النطاقات المتاحة؟    |

الصيغة البرمجية المكافئة هي:

```text
volumeScore       = min(volumeRatio / 2, 1)
acceptanceScore   = 1.00 عند وجود تداخل، وإلا 0.45
narrowRangeScore  = 1.00 إذا كان النطاق قريبًا من الوسيط، وإلا 0.35
totalScore        = round((volumeScore * 0.45
                       + acceptanceScore * 0.30
                       + narrowRangeScore * 0.25) * 100)
```

لا تُقبل المنطقة إلا إذا كان `volumeRatio >= 1.15` و`totalScore >= 45`. مستويات الثقة ثابتة: **High** عند 78 فأكثر، **Medium** من 58 إلى 77، و**Low** فيما دون ذلك.

### 5.3 التصنيف الاتجاهي

التصنيف لا يدعي معرفة نية كبار المستثمرين. هو تصنيف احتمالي محافظ يعتمد على موقع الإغلاق داخل النطاق، تغير الإغلاق مقارنة بالفترة السابقة، وارتفاع الحجم النسبي.

| التصنيف                | القاعدة الأساسية                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------- |
| Potential Accumulation | إغلاق في الجزء العلوي من النطاق، تغير سابق غير سلبي بشدة، وحجم نسبي لا يقل عن 1.15x.   |
| Potential Distribution | إغلاق في الجزء السفلي من النطاق، تغير سابق غير إيجابي بشدة، وحجم نسبي لا يقل عن 1.15x. |
| Neutral                | نقص دليل كافٍ أو تضارب بين الإشارات.                                                   |

لذلك يجب قراءة `Potential Accumulation` بوصفها **منطقة تستحق المتابعة**، وليس أمر شراء، وقراءة `Potential Distribution` بوصفها **منطقة ضغط أو تصريف محتمل**، وليس أمر بيع.

## 6. دورة حياة المناطق

يحدد `activeZoneWindowSessions` عدد جلسات التداول الأخيرة التي تدخل في دمج المناطق. القيم المسموحة هي 5 و10 و20 و30، وأي قيمة غير مسموحة تعود إلى 10 داخل منطق الحماية.

يُرتب النظام المناطق حسب التاريخ، يحتفظ بآخر N تواريخ فعلية، ثم يدمج منطقتين إذا كان اتجاههما متطابقًا وكان تداخل نطاقيهما لا يقل عن 50% من أصغر نطاق. عند الدمج:

- يتسع الحد الأدنى إلى أصغر `lowerPrice` والحد الأعلى إلى أكبر `upperPrice`.
- يُحسب متوسط `volumeRatio` عبر جلسات التقوية.
- تزداد الدرجة بحد أقصى 15 نقطة، وبواقع يصل إلى 5 نقاط لكل جلسة إضافية.
- تصبح الثقة High عند الدرجة 78 أو عند ظهور ثلاث جلسات تقوية، وMedium عند الدرجة 58 أو جلستي تقوية.
- إذا تعارض اتجاهان داخل مجموعة واحدة، يصبح الاتجاه `Neutral` بدل اختيار اتجاه مصطنع.
- تُحفظ `reinforcementSessions` و`lastReinforcedDate` و`activeWindowSessions` للتفسير.

في كل تشغيل يومي، تُوسم مناطق التواريخ الأقدم من تاريخ التشغيل بأنها `historical`، وتُحذف نسخة تاريخ التشغيل السابق قبل إدخال المناطق النشطة الجديدة. يبقى التاريخ متاحًا في التفاصيل، لكن لقطة Overview الحالية تعرض المناطق النشطة الناتجة من آخر تشغيل.

## 7. التحديث اليومي والجدولة

يعمل مسار Heartbeat عبر endpoint:

```text
POST /api/scheduled/daily-egx-analysis
```

تُنشأ الجدولة بعبارة UTC ذات مرشحين للتوقيت الصيفي/الشتوي في القاهرة:

```text
0 30 11,12 * * 1-5
```

يتحقق الخادم داخل المعالج من أن الوقت المحلي هو 14:30 في `Africa/Cairo` قبل تشغيل التحليل. هذا التصميم يضع التحويل إلى المنطقة الزمنية في الخادم بدل الاعتماد على تفسير cron محلي غير ثابت. الجدولة تعمل من المنصة بعد النشر، وليست `setInterval` داخل عملية Node، لأن عمليات Autoscale قد تتوقف عند عدم النشاط.

تسلسل التشغيل اليومي هو:

```text
Heartbeat
  → authenticate cron request
  → resolve owner settings by task UID
  → fetch Yahoo daily OHLCV
  → validate and persist new daily bars
  → analyze sessions and classify zones
  → merge/reinforce active zones
  → mark older zones historical
  → send deduplicated high-confidence accumulation alerts
  → persist analysis run status and alert details
```

المهمة idempotent قدر الإمكان: لا يعاد إدخال daily bar موجود لنفس الرمز والتاريخ، وتُسجل حالات التشغيل `running` و`completed` و`failed`. عند فشل المصدر أو قاعدة البيانات، يُحفظ الخطأ ويُترك للمستخدم كحالة خطأ واضحة.

## 8. هندسة البرمجيات

المشروع تطبيق full-stack TypeScript مبني على React وExpress وtRPC وDrizzle ORM وMySQL/TiDB. يشارك العميل والخادم الأنواع والدوال الحسابية الموجودة في مجلد `shared`، مما يقلل اختلاف العقد بين واجهة المستخدم والخادم.

```text
Browser
  │
  ├─ React 19 + Vite + Tailwind 4 + shadcn/ui
  │       │
  │       └─ TanStack Query / tRPC client
  │
  └─ /api/trpc
          │
          ├─ Express 4
          ├─ tRPC 11 routers
          ├─ publicProcedure للقراءة العامة
          └─ protectedProcedure للإعدادات
                  │
                  ├─ server/db.ts
                  ├─ Drizzle ORM
                  └─ MySQL/TiDB

Heartbeat → /api/scheduled/daily-egx-analysis → server/runAnalysis.ts
Yahoo Finance Chart API → server/marketData.ts
```

```text
trpc.dashboard.history
trpc.dashboard.alertHistory
trpc.dashboard.stock({ symbol })
```

أما `settings.get` و`settings.save` و`settings.enableDailySchedule` فهي مسارات محمية. يستخدم الخادم `publicProcedure` للقراءة العامة و`protectedProcedure` لتعديل الإعدادات وتشغيل الجدولة، ولا يعتمد العميل على Axios مخصص للوصول إلى هذه المسارات.

## 9. سياسة عدم تصنيع البيانات

تطبق السياسة في أكثر من طبقة:

1. لا تُقبل صفوف Yahoo إذا كانت قيم OHLCV غير صالحة.
2. لا تُنشأ صفوف بديلة للرموز التي لا ترد من المصدر.
3. لا تتحول البيانات اليومية إلى شموع ساعتين وهمية.
4. لا تظهر شارات اتجاه أو تأكيدات عند غياب المناطق أو فشل اللقطة.
5. لا تعرض بطاقات المؤشرات أرقامًا افتراضية لتعويض `null` أو مصفوفة فارغة.
6. لا تُرسل تنبيهات عند غياب مناطق High Potential Accumulation حقيقية.
7. تُحفظ أخطاء التشغيل وحالات عدم وجود البيانات بدل إخفائها خلف قيمة تبدو واقعية.

هذه السياسة مهمة خصوصًا لأن بيانات السوق قد تتأخر أو تتغير تغطيتها أو تختلف عن آخر اقتباس حالي. يسجل [free_source_research.md](./free_source_research.md) نتائج فحص المصدر وقيود إعادة التوزيع، بينما يحافظ الكود على آخر إغلاق تاريخي تم التحقق منه فقط.

## 10. التطوير المحلي

### المتطلبات

- Node.js 22 أو إصدار متوافق.
- pnpm.
- MySQL/TiDB عبر `DATABASE_URL`.
- متغيرات Manus النظامية عند تشغيل المصادقة والجدولة.

### تثبيت وتشغيل

```bash
pnpm install
pnpm dev
```

يبدأ الخادم في وضع التطوير عبر `server/_core/index.ts`، ويخدم واجهة Vite وواجهات Express/tRPC. لا تضع الأسرار في المستودع ولا تلتزم بملف `.env`.

### أوامر الجودة والبناء

```bash
pnpm test       # تشغيل Vitest
pnpm check      # TypeScript بدون إخراج ملفات
pnpm build      # Vite + esbuild للخادم
pnpm format     # Prettier
pnpm start      # تشغيل build الإنتاجي
```

### مخطط قاعدة البيانات

بعد تعديل `drizzle/schema.ts`، اتبع ترتيبًا محافظًا:

```bash
pnpm drizzle-kit generate
```

راجع SQL الناتج، ثم طبّق الهجرة على قاعدة البيانات عبر مسار إدارة قاعدة البيانات المعتمد. لا تستخدم أوامر حذف جماعية على قاعدة الإنتاج، ولا تنشئ بيانات اختبار تشبه بيانات السوق الحقيقية.

## 11. الاختبارات

يستخدم المشروع Vitest مع اختبارات للمنطق المشترك والخادم واختبارات سلوكية لمكونات React. تغطي الاختبارات التجميع، الدرجات، الثقة، الاتجاه، الترتيب، التأكيد بعد 1/3/5 جلسات، دورة حياة المناطق، التنبيهات، سجل التنبيهات، حالات no-data، وحواجز عدم التصنيع.

قبل تسليم تغيير جديد، شغّل:

```bash
pnpm test && pnpm check && pnpm build
```

الاختبارات السلوكية للواجهة لا تستبدل الاختبارات الحسابية، كما أن نجاح TypeScript لا يغني عن فحص حالات التحميل والخطأ بصريًا في المتصفح.

## 12. النشر والمزامنة

النشر المستضاف حاليًا هو Manus WebDev، مع نطاق عام ثابت. المشروع مضبوط على **Auto-publish**؛ حفظ checkpoint ناجح ينشر الإصدار تلقائيًا. عند تحديث GitHub، استخدم الفرع `main`:

```bash
git status
git add README.md
git commit -m "docs: add comprehensive Arabic README"
git push origin main
```

بعد النشر، تحقق من أن الداشبورد يعيد HTTP 200 وأن `main` يحتوي على commit الإصدار نفسه. لا تنشر أسرارًا أو بيانات اتصال قاعدة البيانات أو cookies داخل المستودع.

## 13. استكشاف الأخطاء

| العرض                        | الفحص الأول                                                                                                       |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `No data`                    | راجع تاريخ آخر إغلاق، تغطية الرمز، ونتيجة المصدر، ولا تفترض أن قيمة الاقتباس الحالي تعني وجود OHLCV تاريخي مكتمل. |
| `Awaiting first run`         | تحقق من وجود Heartbeat مفعّل ومن موعد التشغيل في أيام العمل.                                                      |
| `Alert not run`              | راجع `analysis_runs`؛ قد لا توجد منطقة High Accumulation حقيقية أو قد يكون التنبيه skipped.                       |
| عدم ظهور تغيير نافذة المنطقة | التغيير pending حتى التشغيل اليومي التالي، ولا يعيد آخر تشغيل بأثر رجعي.                                          |
| فشل Settings                 | تحقق من جلسة Manus OAuth؛ الصفحة العامة لا تحتاج تسجيل دخول، لكن الإعدادات محمية.                                 |
| فشل build أو types           | شغّل `pnpm check` ثم راجع آخر ملف معدل وسجل الخادم قبل أي rollback.                                               |

## 14. حدود الاستخدام والتفسير

هذا النظام يحدد **مناطق اهتمام تحليلية** من السعر والحجم المسجلين. لا يرى النظام أوامر المستثمرين أو هوية المشاركين، ولا يمكنه إثبات أن “الكبار” يشترون أو يبيعون. التصنيف الاتجاهي احتمالي ومحافظ، وارتفاع الحجم قد ينتج عن أخبار أو إعادة توازن أو أحداث سيولة وليس عن تجميع مؤسسي.

كما أن وضع البيانات المجانية الحالي يومي، وبالتالي لا يصلح لبناء استنتاجات دقيقة عن توزيع الحجم داخل الجلسة أو قراءة كل ساعتين. يجب تفسير النتائج مع حجم العينة، جودة التغطية، وتاريخ آخر جلسة مكتملة.
